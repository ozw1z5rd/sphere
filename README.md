# Sphere

Native local AI assistant for macOS (SwiftUI + AppKit), with draggable MCP
modules, brokered file access and permissions, per-window screen capture, and a
plug-in contract for the knowledge base.

> Status: **Phase 0/1** — complete, working scaffold. Chat with
> OpenAI-compatible/Anthropic providers, stdio MCP runtime, module installation,
> filesystem broker with counters, screen capture with allowlist, CLI.

## Requirements

- macOS 13+ (tested on macOS 13.7.8)
- Xcode 15.2 / Swift 5.9.2 (no external dependencies: system SDK only)
- `python3` and/or `node` only if you use the example modules based on those runtimes

## Build and run

```bash
swift build                 # compile everything
swift test                  # 59 tests (manifest, policy, store, tools, installer)
swift run Sphere            # launch the GUI app
swift run sphere-cli help   # launch the CLI
```

### Create the macOS app (.app)

```bash
./scripts/build-app.sh              # release build -> dist/Sphere.app
./scripts/build-app.sh release --open# build and run
./scripts/build-app.sh debug        # debug build
```

The bundle is signed ad-hoc (`codesign --sign -`) so macOS keeps the TCC
permission (Screen Recording) associated with the app's identity. No
Developer ID is needed for local use; distributing to others requires
notarization.

Open the app by double-clicking `dist/Sphere.app` or with `open dist/Sphere.app`.


The app automatically creates:

```
~/Library/Application Support/Sphere/
  sphere.sqlite     sessions, modules, grants, audit
  config.json       provider and preferences
  secrets.json      API key (permissions 0600)
  Plugins/          installed modules
  Store/            original .spheremodule archives
  Captures/         screenshots
  Logs/sphere.log   application audit log
  Logs/http.log     provider requests/responses
  Logs/keychain.log Keychain/secret accesses
```

API keys live in `secrets.json` (0600); the Keychain is only used for the
one-time import. In **Settings → Diagnostica** (Diagnostics) you can enable full
HTTP logging, open the logs, and import the keys from the Keychain.

## Quick start

1. `swift run Sphere` (or `./scripts/build-app.sh release --open`)
2. **Sphere → Settings…** (`Cmd+,`) → choose the active provider (by default:
   Ollama at `http://localhost:11434/v1`; OpenAI, Anthropic and DeepSeek are
   also available), set the base URL and model, save the API key if
   required.
3. **Modules** → drag a `.spheremodule` file (or use *Install module…*),
   then enable the module with the toggle.
4. **File Access** → *Grant folder (RO/RW)* to authorize the paths the agent
   can read/write. Read/write counters are shown for each path.
5. **Screen** → *Request Screen Recording*, *Refresh windows*, then *Allow* on
   the individual windows the AI may capture.
6. **Network** → the web tool is already active; add URLs, domains or
   IP/CIDR ranges to block here. Recent requests are listed in the tab.
7. **Chat** → type and send. You can drag files (chips with name/type),
   enable/disable voice with the *Voce* (Voice) checkbox, and use the fonts
   chosen in **Settings → Aspetto** (Appearance).
8. **Sphere → About Sphere** shows the company logo; the app icon is the
   circuit brain generated by `scripts/generate-icon.sh`.

## Built-in tools

Besides MCP modules, Sphere ships in-process tools:

- **Files**: `fs_read` (optional line range), `fs_write`, `fs_list`, `fs_glob`,
  `fs_grep` (binary-aware, context lines, counts, `.gitignore`), `fs_stat`
  (size/mtime/mode/magic-byte type), `fs_read_bytes` (hex/base64, max 4 KB),
  `fs_edit` (search/replace or unified patch) and `fs_select` (JSON/YAML/plist
  path selector, or `lines:START-END` for text such as `Package.swift`).
- **Images**: `image_inspect` (format, dimensions, DPI, minimal EXIF, optional
  PNG thumbnail).
- **Git (read-only)**: `git status|diff|log|show|blame` inside a granted path.
- **System**: `system_info` (date, OS, host, granted roots) and clipboard
  read/write.
- **Web**: `web_fetch` plus `web_search` (DuckDuckGo HTML results).
- **Exec (opt-in)**: `exec` runs an allowlisted argv (no shell) inside a
  granted directory, with a timeout, no network and writes limited to the
  granted root via `sandbox-exec`. Enable it in **Settings → Tools**.

The session cost uses the provider price table (DeepSeek: cache-hit/cache-miss
input, output and peak windows) and grows with the tokens recorded for each
request.

The **Tools** tab lists every tool exposed to the model and lets you enable or
disable each one (all enabled by default; disabled tools are hidden from the
catalog and rejected if called) and shows the latest 200 tool calls. A dedicated
**Clipboard** tab controls clipboard read/write, offers an optional local
preview and shows the clipboard log. A dedicated **Logs** window (opened from
Settings or the status bar) shows the last 200 file-access, network, tool,
clipboard, HTTP and Keychain operations in the same console view; database logs
include the session number (`#N`).

## Principles

- **Self-describing modules**: the `module.json` is written by the module
  author, not the user. The user downloads/drags and enables.
- **Everything per-user** in Application Support: no admin privileges.
- **Brokered file access**: IO goes through the broker, so the counters and
  RO/RW grants are authoritative.
- **Explicit screen access**: TCC is per-app; Sphere adds an internal
  per-window consent with default deny.
